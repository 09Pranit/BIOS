# Tin Computer connection readiness

Tin Computer is credited as the BIOS growth partner. **This repository is not connected to Tin Computer, GitHub analytics, or any growth automation.** No growth result or account authorization is claimed.

The public route is pre-rendered, semantic HTML. Its build produces canonical and Open Graph metadata, JSON-LD, a sitemap, robots exclusions for operator routes, and local font files with licenses. `SITE_URL` must be set to the real public origin before building for a deployment. The included local Lighthouse audit is a measurement of the local production build, not a promise about a future host.

To connect later, follow Tin's [official onboarding workflow](https://tin.computer/workflows/growth-plan) and [official repository instructions](https://github.com/tin-computer/tin). A project owner can create a Tin project, connect only the intended GitHub repository, and separately grant read access to a chosen analytics/Search Console property. Begin with a reviewable growth plan or site-health audit. Keep proposed code changes in pull requests that the project owner reviews. Public messages, spend and analytics permissions need their own explicit approval.

Suggested success funnel: landing visit → judge/operator login → first lab run → evidence inspected → counterfactual completed → report reviewed. If analytics are connected, collect aggregate events and synthetic case IDs only. Never export operator tokens, log bodies, evidence containing personal data, or production citizen records. No analytics SDK is embedded by default.

Useful first experiments are a clearer landing-to-lab entry, a more understandable uncertainty explanation, and checking whether users open the evidence behind a diagnosis. Measure completion and comprehension; do not optimize toward unwarranted high-confidence conclusions.
