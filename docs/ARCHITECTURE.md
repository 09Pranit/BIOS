# Architectural decisions

The delivered scope centers on correctness that can be demonstrated locally. The two source briefs disagree about attendance semantics; the stricter policy wins: incompatible concurrent marks require review.

1. Immutable operations are the source of truth. Materialized records are derived deterministically. The HLC is useful for provenance and clock validation, but causal ancestry decides whether edits are sequential or concurrent.
2. Critical fields use a multi-value register. Its frontier contains versions not causally superseded by another operation. Equal concurrent values agree; incompatible values produce an explicit conflict and a `null` unresolved field. All original ops remain in the log. A human resolution references the known frontier, preserving concurrent future alternatives.
3. Append-only fields union operation IDs; a visit or a dose cannot vanish because another worker wrote a different field. Tags remove only observed matching adds, so an independent add survives. Counter totals sum unique signed deltas.
4. Deletion is a tombstone, not a row delete. Concurrent edits produce a conflict carrying both the tombstone and competing edit. A causal false tombstone provides resurrection. Deleted child profiles remain addressable by internal ID and keep history.
5. The client stores an encrypted state aggregate for a small-school demo. That single Dexie transaction makes data and outbox inseparable. A serialized write queue prevents async encrypt/write races. Scaling requires per-op encryption and a causal index; whole-log recomputation intentionally favors auditable simplicity.
6. Hub `BEGIN IMMEDIATE` + unique op IDs + FULL synchronous WAL commits establish the acknowledgement boundary. Immutable checksums reject reuse of an operation ID with changed content. Push/pull batches are bounded by payload bytes and count. Cursor commit happens in the same local transaction as the received operations.
7. A sync fault after server commit but before acknowledgement leaves pending work locally. Replaying the exact signed batch returns the existing IDs without duplicating effects. A fault during pull resumes from the last local committed cursor, not from an in-memory request position.
8. Node built-in SQLite replaces better-sqlite3 to avoid native installation friction. Charts use lightweight SVG/CSS and real operation counts, rather than adding d3/Recharts for decorative graphics. The custom domain CRDT is covered by property tests but not externally audited.
9. A canonical whole-log SHA-256 comparison demonstrates equality after full transfer. It is not called a Merkle repair tree. Future district replication should add authenticated membership federation, Merkle partitions, causal compaction and explicit key management.
10. Optional services sit outside the data path. None is required or falsely shown as connected. The demo makes no clinical diagnosis or verified school/community adoption claim.
